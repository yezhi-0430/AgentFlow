## 数据与服务

- **工作流定义与运行记录**已持久化到本地 SQLite；后端重启后定义可恢复，历史运行可回看。
- **模型密钥不落库**：重启后恢复的工作流处于"需要重新提供 API Key"状态；执行时必须显式传入密钥（只在内存中，不写入数据库/日志/追踪）。
- 当前运行的消息只保存在内存中；页面刷新后可从运行记录接口重新读取已完成的步骤与输入输出，但"进行中的实时消息时间线"不持久化。
- 后端没有登录鉴权，CORS 面向本地开发，不适合直接暴露到公网。
- 不同浏览器标签页可能同时操作同一工作流；同一工作流的并发执行会被拒绝（409），不会排队。
- 可选本地 API Token（`AGENTFLOW_API_TOKEN`）：设置后 `/api/*` 需要 Bearer Token；默认不启用，且前端 `VITE_API_TOKEN` 会进入浏览器包，只适合本地/受信环境，不替代生产鉴权。
- 定义可导出/导入（`GET /api/workflows/{id}/definition`、`POST /api/workflows/import`）：定义版本 `schema_version=1`，导入会校验并剔除密钥字段，导入总是分配新的 `workflow_id`；导入/恢复后的工作流同样需要重新提供密钥。

## 执行模式

- **顺序执行**：已接通创建、执行、步骤状态、消息与运行记录；失败即停，不把失败内容交给下游。
- **并行执行**：已接通全部成功 / 部分失败 / 全部失败 / 停止取消的记录与状态。
- **层次协作**：协调者规划 → 工作者执行 → 协调者汇总；至少 2 个智能体。工作者按顺序执行（不是并行 worker 池）。
- **辩论模式**：多辩手最多 2 轮、第二轮互看观点 → 裁判综合；至少 3 个智能体。
- **投票模式**：多候选独立作答 → 裁判比较裁决；至少 3 个智能体。这里的“投票”是裁判裁决，不是严格的多数票计票。
- **动态协作**：协调者每轮输出 JSON 选择下一位工作者，最多 `max_iterations` 轮，最后汇总；至少 2 个智能体。协调者输出非法时回退到第一位工作者并标记 partial。
- **群聊协作**：共享 transcript；可选 Lead 分派/总结，或成员 round-robin + `@点名` / 结构化 handoff；最多 6 人、最多 20 轮，不支持工具调用/无限互相委派；前端有独立「群聊」导航，群聊消息持久化到 SQLite（重启可回放）。
- 网页端按模式自动分配协调者/工作者/辩手/裁判角色，但不能编辑专用角色提示词；需要自定义提示词时请用 Python 配置或定义导入。

## 停止、暂停与重试

- 停止已接入真实执行控制：顺序模式在步骤边界阻止后续调用；并行模式取消未完成调用；前端已提供「停止运行」按钮（stopping → stopped，409 表示当前没有活动运行）。
- 暂停/恢复目前只是状态标记，不会中断进行中的模型调用。
- 支持可选的单步超时与重试（`AGENTFLOW_STEP_TIMEOUT_SECONDS`、`AGENTFLOW_MAX_ATTEMPTS`，默认关闭/1 次）。只有超时、限流、网络、服务端错误会重试；鉴权/参数错误不重试。
- 多次尝试的用量按已知部分累计，未知尝试会使 `usage_type=partial/unknown`；不做费用估算。
- 已取消/已停止的步骤，其远端推理是否真正终止无法确认，用量记为 `unknown`，不按 0 计。

## 运行记录与用量

- 运行记录保存在本地 SQLite（默认 `backend/agentflow_data.db`，可用 `AGENTFLOW_DB_PATH` 覆盖），旧库会自动补齐新列。
- 记录格式 `schema_version=3`：步骤输入输出、模型、finish_reason、状态、错误类型、尝试次数、时间与用量类型；run 带 `trace_id`（追踪启用时）。
- 写入通过 `asyncio.to_thread` 移出事件循环并在仓储层串行化；运行开始、每个步骤后与终态各保存一次。
- 保留策略：`AGENTFLOW_MAX_RUNS`（默认 1000，0 不限制）与 `AGENTFLOW_RUN_RETENTION_DAYS`（默认 0）；单步文本落库前按 `AGENTFLOW_RECORD_TEXT_LIMIT` 截断（默认 20000 字符），错误文本做保守脱敏。
- 进程在单步调用中途被杀时，该步骤可能停留在 running，需要结合 run 状态与 error 判断。
- 历史回看只读本地记录，不调用模型；"重新执行"会创建新 run_id，可能产生新费用。
- 运行历史筛选在前端对当前已加载页进行；接口暂不支持 `status` 查询参数。

## 追踪与评分（可选）

- Langfuse 追踪默认关闭（`ENABLE_LANGFUSE_TRACING=false`）；缺少 SDK/密钥或导出异常都不影响业务。
- 内容采集默认关闭（`LANGFUSE_CAPTURE_CONTENT=false`），默认不上传任务、输入输出、错误正文与评分理由；开启后会先做密钥/连接配置脱敏。
- Langfuse 不可用时不重试排队；本地记录不受影响。
- 自动评估（`AUTO_EVALUATE`）会调用真实评审模型并产生少量费用，默认关闭；评审失败只记日志，不改变工作流结果。
- 评分只写入 Langfuse；本地数据库不存评分记录。

## Harness²-lite 实验对比

- **仅有一次性真实实验**：10 个固定 case × 3 候选、单一模型、单轮运行；通过率只是该数据集上的观察，不能外推总体质量，也不能证明某种编排更优。
- **主分数是确定性 rubric**（关键词匹配）；独立 LLM judge 只做增量记录，不覆盖主分数，judge 失败/超预算/缺失不会把 case 标成通过。judge 与 rubric 在部分 case 不一致（本次一致率 8-9/10），说明单一评分器不足。
- **证据默认关闭**：`AGENTFLOW_EVIDENCE_ENABLED=true` 或实验 `--evidence` 才保存；只写本地 `backend/evidence/`（已 gitignore），90 天保留、单文件 200KB 上限，写入前脱敏。证据包含请求/响应等业务内容，开启前请确认合规。
- 候选 ID 为 `<experiment_id>-<config>`（core 表全局唯一约束）；显示名仍是 single/sequential/parallel。
- 不实现 Harness² 的自动 Propose–Probe–Compose 递归改进与自动发布；也不接入其基准套件。
- 对比数据来自本地 SQLite 与 runner JSON；Langfuse 只提供 trace，不保存对比结论。

## 模型

- 优先使用 OpenAI 或 OpenRouter 的对应连接。OpenRouter 的 Key 不能直接提交给 OpenAI 官方接口。
- 模型选项是配置快照，服务商可变更模型可用性、权限与名称，应以自己的服务商控制台为准。
- 当前 Claude 适配器走 OpenAI 兼容接口，默认地址是 OpenRouter；不等同于已完成的 Anthropic 原生 API 接入。
- 本地模型尚未接入，创建页面会提示暂不支持。

## 评测

- 已提供固定数据集、冻结配置与假适配器实验入口（`experiments/`、`backend/scripts/run_experiment.py`）。
- 默认实验使用假模型，只能证明机制与记录链路；**不是真实模型质量或成本的证据**。
- 真实模型实验需要显式设置 `AGENTFLOW_EXPERIMENT_REAL=1` 并提供密钥；本批未运行，因此没有真实质量/延迟/成本数字。
- 评分器为关键词 rubric、样本仅 5 条，不具统计代表性；评分失败、缺失评分会分别记录，不会只平均成功案例来宣称总体成功率。

## 部署

- Docker Compose 与启动脚本只面向本地体验，不包含生产级鉴权、多租户隔离、反向代理或高可用。
- 前端没有浏览器端到端自动化测试；当前验证为 Node 测试 + lint + 构建，以及后端 API 契约测试。
